# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Filotaxia** is an installable web app (PWA, phone first — people scan the QR with their phone) for living terrariums that make sound: each terrarium has a QR in its base; scanning it opens the terrarium's page, which adds it to the collection on that phone (only scanning connects a terrarium), and the person can listen to its piece. The first one scanned becomes **Mi terrario** (their own), with its care status and reminders. **No accounts, no login**: the scan is enough.

- Visual system: **read `DESIGN.md` before building any UI.** Light and dark themes (Ajustes → Apariencia: Auto / Claro / Oscuro). White, black and the web's neutral greys only — **no accent colour** (no green or anything else); regular-weight titles, small uppercase eyebrows, black pill buttons, thin lines.
- Structure (router, store, header, floating bottom nav, sheets, toasts) comes from Pulso (`inspo/pulso`, the owner's own project). `inspo/` is reference material only — never import from it. `inspo/proyecto-filotaxia` is the filotaxia.com website (Vite + GSAP): assets are copied **optimized** into `src/assets/` (its originals weigh ~325 MB), never linked.
- The owner is a web designer who wants to understand all the code: keep it clear, comment in Spanish where it helps, no over-engineering. UI copy is Spanish (es-AR).

## Data and hosting

- **Catalog in Supabase** (project "App", org Filotaxia, `sa-east-1`, free plan): table `terrarios`, one row per terrarium. Schema changes are SQL migrations in `supabase/migrations/` (apply them with the Supabase connector or the SQL Editor, and keep the file name = the version the database records). `qr_code` is generated by the database and a trigger forbids changing it; nothing can be deleted (retire it: `status = 'retirado'`). Anyone can read `publicado`/`retirado` rows (RLS); `borrador` rows and all writes are for the admin panel: only emails in the `admins` table (`is_admin()`, checked by RLS) can insert/update rows and upload to the public Storage bucket `terrarios` (one folder per terrarium, `07/foto-<timestamp>.jpg`; files are never overwritten or deleted).
- **Only `src/store/catalog.js` (public app) and `src/store/admin.js` (panel) talk to Supabase**, with `fetch` (no library) and the publishable key in `src/store/supabase-config.js` (public on purpose; the secret key never goes in this public repo).
- **`catalogo.json`** is a copy of the published catalog, written by `.github/workflows/catalogo.yml` twice a day (that run also keeps the free Supabase project awake: Supabase wants "a few requests per day" — one every 2 days wasn't enough and the project got paused in October 2026; scheduled workflows only run from `main`). The app falls back to it when Supabase doesn't answer.
- **Backups**: every Monday 06:00 UTC a pg_cron job (`backup-semanal`) calls `take_backup('semanal')`, which stores every `terrarios` row (borradores too) plus the `admins` emails as one jsonb row in the `backups` table (admins-only read; no API writes; never deleted). The panel's `#/backups` lists them, downloads them as JSON and makes one on the spot (`make_backup()`, checks `is_admin()`). Data only: files stay in Storage. This does NOT keep the project awake (it only runs while it's awake). How to restore a row: comment at the end of `supabase/migrations/20261027133539_backups.sql`.
- **Hosting: GitHub Pages** from `main`, custom domain `app.filotaxia.com` (`CNAME` file; DNS `CNAME app → filotaxia.github.io` at Hostinger). `filotaxia.com` itself stays at Hostinger.

## Running the Project

No build, no package.json, no npm dependencies. Serve the root with any static server (ES modules don't work over `file://`):

```bash
npx serve . -l 4180
```

Logic tests (pure functions in `src/utils/` — including the MIDI file reader `utils/midi.js` — and `src/audio/score.js`) use Node's built-in runner. Always pass the glob — a bare `node --test` would also pick up the tests inside `inspo/`:

```bash
node --test 'tests/**/*.test.js'
```

## Architecture

Vanilla HTML, CSS and JS (ES modules). Font: PP Neue Montreal (same as filotaxia.com), local in `src/assets/fonts/` via `styles/base/fonts.css` — 400 and 500 both use the Medium cut, like the web (personal use only; publishing needs the app/web license). External: jsQR (scanner fallback), qrcode-generator (the panel's QRs) and GSAP (the ficha's "Cómo funciona" image swap; without it the image changes with no animation) loaded on demand from jsDelivr; the 4 layer videos (Manifiesto, Escuchar) are filotaxia.com's giphy GIFs converted to light local MP4 loops in `src/assets/videos/capas/` (400px, no sound, ~1.3 MB for all four instead of 49 MB of GIFs, which made the Manifiesto slow on phones), shown with `<video muted loop playsinline autoplay>` (to be replaced by own videos).

### Phone

- **QR — they never die.** Each printed QR is `https://app.filotaxia.com/t/<qr_code>` (6 chars from `abcdefghjkmnpqrstuvwxyz23456789`, never changes). GitHub Pages serves `404.html` for that path, which `location.replace`s to `/#/t/<qr_code>`; the `t/:code` route (`views/qr`) finds the terrarium (`findByQr`, asking Supabase again if the local copy doesn't have it) and opens its ficha as a scan. The in-app scanner reads the same link (`utils/qr.js` → `parseQrLink`); old number formats (`04`, `filotaxia:04`, `#/terrario/04`) no longer connect. Never print a QR with another domain (`*.github.io`, localhost). The panel (`/admin/`) draws, downloads (SVG/PNG) and prints them (error correction H; `qrLink`/`qrSvg` in `utils/qr.js`), with the isotipo small in the centre: a blank hole of whole modules (`logoLayout`/`clearHole`, 9×7 of 33×33, ~6% of the modules; the logo fills it, 8.4 modules wide) so most of H's ~30% stays free for dirt and scratches — don't make the hole bigger (tested: 11×7 and up read worse when dirty); to make the logo more visible, print the QR bigger.
- **Camera needs HTTPS** (or localhost). Over the LAN (`http://192.168…`) the scanner shows the "insecure" hint; publish over https to test it on a phone.
- **iPhone audio:** `navigator.audioSession.type = "playback"` so Web Audio plays with the silent switch on; the player resumes the AudioContext when the app comes back to the foreground.
- **iOS caveat:** an installed PWA has its own storage, separate from Safari — terrariums scanned in Safari don't show up in the installed app (scanning again adds them).

### Mi terrario (`#/mi-terrario`)

Care page modeled on an energy app's "Status." screen: "Filotaxia." + "Armonía en plantas." in grey (the Ajustes dot at the right), the terrarium's code as the hero big number ("TR01", `codeOf()` in `content/terrarios.js`) with a "+ info" chip → its ficha (`#/terrario/:id`, every spec; it used to be a "Creado 22/07/2026" chip, and before that the last scan) and "Escuchar" → the player, then blocks (`components/block`): the terrarium photo full width → its ficha, Bitácora (note count → `#/bitacora/:id`) | Pieza (the piece's duration; the whole block → the player, the QR in its corner → Conectar), Plantas (`components/plants-block`), and a full-width "Cuidados." card → `#/mi-terrario/cuidados`, a subpage with Riego, the general care guide (riego · luz · sustrato, same for every terrarium) and the care FAQ; its route starts with `mi-terrario` so the nav keeps that section active. Air humidity is no longer shown, and the status sentence (`careStatus` in `utils/care.js`) is not used on screen for now. Ventilación is not shown anywhere (the owner's call, for every terrarium; `care.ventilacion_days` stays in the data and the panel); Riego has no button for now (it counts from the last logged watering, or from the scan day); humidity drops with the days since the last watering. **Readings are simulated** (seeded by terrarium + day, `utils/care.js`) until terrariums have sensors. Terrariums with `plants` show a Plantas block (leaf shape per plant; its "Ondas" toggle swaps to each plant's wave). "Hecho hoy" only reflects a real log entry (`loggedToday`), never the scan-day fallback.

Photos: `terrario.photo` points to `src/assets/images/terrarios/` (the product shots from filotaxia.com's Terrarios page, TR01–06: a 760px square of the 1372×832 originals in `inspo/proyecto-filotaxia/src/assets/images/productos/FINALES/`, centred on the glass, resized to 800px; same square for all six, so they look the same size). Plant photos live in `src/assets/images/plantas/` (360px webp) and show in the Plantas block with the plant's wave. ### Panel (`/admin/`)

Internal page, no link from the app, `noindex`. `admin/index.html` + `src/views/admin/` (`admin.js`: its own small hash router `#/` list · `#/nuevo` · `#/editar/07` · `#/imprimir` · `#/backups`, login, list; `admin-form.js`: every column of `terrarios`, the 4 files, status buttons; `admin-qr.js`: QR via qrcode-generator, SVG/PNG download; `admin-backups.js`: the weekly backups list, JSON download and "Hacer backup ahora"). Login is Supabase Auth email + password (new signups disabled in the dashboard; users are created in Authentication → Users); writing needs the email in `admins` (edited in the SQL Editor, not through the API). Saving: validate (and parse the MIDI files with `utils/midi.js` so a broken one never uploads) → upload chosen files (photo shrunk with `utils/image.js`) → insert/update the row. New terrariums start as `borrador`; buttons only move forward (borrador → publicado → retirado → publicado), never back to borrador and never delete — the database enforces the same. An empty duration is taken from the longest MIDI.

### Views

Each view exports `title` (string or `(ctx) => string`), optionally `subtitle` (same), `header` (true → big header: title + subtitle + Ajustes dot), `nav` (false → no bar, the splash; or `(ctx) => boolean`: the Manifiesto hides it only in the first-scan onboarding), `back` (string or `(ctx) => string`), and `render(root, ctx)` with `ctx = { params, from }` (`from` = the previous route, e.g. `"coleccion"`). If `render` returns a function, the router calls it when leaving (stop the camera, destroy the audio player). Full-height screens use `.screen` (+ `.screen__actions` pinned to the bottom).

### Data rule

**No view, component or layout file touches `localStorage`, IndexedDB or Supabase directly.** Everything goes through `src/store/` (`store.js`; Bitácora photos via `bitacora.js` → `photos.js`; the catalog via `catalog.js`). To sync with a backend later, replace `collection.js` / `local.js` / `photos.js`; views don't change.

### Components

Plain functions that return HTML strings. **Every user-provided value goes through `escapeHTML()`** (`src/utils/html.js`). Event listeners are attached by the view after inserting the HTML.

### CSS

`src/styles.css` is the single CSS entry; register every new CSS file there under its group. Views and components use **semantic aliases only** (`--color-text`, `--color-line`…), never raw tokens or hex values — otherwise they ignore the theme.

Theme: every alias in `semantic-colors.css` is `light-dark(light, dark)`. **Light is the default** (`prefs.theme: "light"`; `index.html` starts with `data-theme="light"` so there's no dark flash). No `data-theme` = follow the phone ("Auto"); `data-theme="light|dark"` on `<html>` forces it (`utils/theme.js`, from `prefs.theme`, applied in `main.js` before the first render and on every `prefs` change).

Units: an existing token if one fits; otherwise plain `px`. Never `clamp()`, `vw`, `rem`/`em`. Exceptions: `vh`/`dvh` for heights, `%` for widths, `env(safe-area-inset-*)`.

Mobile first (375px is the source of truth). `min-width` media queries only, ascending, at the end of each CSS file after this banner:

```css
/* ============================================
RESPONSIVE
============================================ */
```

Breakpoints: 480 · 640 · 768 · 1024 (bottom nav becomes side rail) · 1280 · 1400.

### File Headers (CSS & JS)

Every CSS and JS file starts with this exact 3-line banner — group and name, separated by an em dash:

```css
/* ============================================
   Views — Escuchar
   ============================================ */
```

Groups: `Tokens`, `Semantic`, `Base`, `Layout`, `Animation`, `Components`, `Views`, `Store`, `Content`, `Audio`, `Utils`, `App`, `Tests`.

### Accessibility baseline

Tap targets ≥ 44px (`--size-tap`), visible focus (`:focus-visible`), icons next to text get `aria-hidden="true"`, the router moves focus to the screen title on navigation, errors are shown with words (not only a color).
