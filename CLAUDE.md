# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Filotaxia** is an installable web app (PWA, phone first — people scan the QR with their phone) for living terrariums that make sound: each terrarium has a QR in its base; scanning it opens the terrarium's page, which adds it to the collection on that phone (only scanning connects a terrarium), and the person can listen to its piece. The first one scanned becomes **Mi terrario** (their own), with its care status and reminders. **No accounts, no login**: the scan is enough.

- Visual system: **read `DESIGN.md` before building any UI.** Light and dark themes (Ajustes → Apariencia: Auto / Claro / Oscuro). White, black and the web's neutral greys only — **no accent colour** (no green or anything else); regular-weight titles, small uppercase eyebrows, black pill buttons, thin lines.
- Structure (router, store, header, floating bottom nav, sheets, toasts) comes from Pulso (`inspo/pulso`, the owner's own project). `inspo/` is reference material only — never import from it. `inspo/proyecto-filotaxia` is the filotaxia.com website (Vite + GSAP): assets are copied **optimized** into `src/assets/` (its originals weigh ~325 MB), never linked.
- The owner is a web designer who wants to understand all the code: keep it clear, comment in Spanish where it helps, no over-engineering. UI copy is Spanish (es-AR).

## Data and hosting

- **Catalog in Supabase** (project "App", org Filotaxia, `sa-east-1`, free plan): table `terrarios`, one row per terrarium. Schema changes are SQL migrations in `supabase/migrations/` (apply them with the Supabase connector or the SQL Editor, and keep the file name = the version the database records). `qr_code` is generated by the database and a trigger forbids changing it; nothing can be deleted (retire it: `status = 'retirado'`). Anyone can read `publicado`/`retirado` rows (RLS); `borrador` rows and all writes are for the admin panel (Plan 2, `docs/superpowers/`).
- **Only `src/store/catalog.js` talks to Supabase**, with `fetch` (no library) and the publishable key in `src/store/supabase-config.js` (public on purpose; the secret key never goes in this public repo).
- **`catalogo.json`** is a copy of the published catalog, written by `.github/workflows/catalogo.yml` every 2 days (that run also keeps the free Supabase project awake). The app falls back to it when Supabase doesn't answer.
- **Hosting: GitHub Pages** from `main`, custom domain `app.filotaxia.com` (`CNAME` file; DNS `CNAME app → filotaxia.github.io` at Hostinger). `filotaxia.com` itself stays at Hostinger.

## Running the Project

No build, no package.json, no npm dependencies. Serve the root with any static server (ES modules don't work over `file://`):

```bash
npx serve . -l 4180
```

Logic tests (pure functions in `src/utils/` — including the MIDI file reader `utils/midi.js` — and `src/audio/score.js`) use Node's built-in runner. Always pass the glob — a bare `node --test` would also pick up the tests inside `inspo/`:

```bash
node --test 'tests/**/*.test.js'
```

## Architecture

Vanilla HTML, CSS and JS (ES modules). Font: PP Neue Montreal (same as filotaxia.com), local in `src/assets/fonts/` via `styles/base/fonts.css` — 400 and 500 both use the Medium cut, like the web (personal use only; publishing needs the app/web license). External: jsQR (scanner fallback) and qrcode-generator (`imprimir-qr.html`) loaded on demand from jsDelivr; the 4 layer GIFs in the Manifiesto are hotlinked from giphy, like filotaxia.com (to be replaced by own videos).

### Phone

- **QR — they never die.** Each printed QR is `https://app.filotaxia.com/t/<qr_code>` (6 chars from `abcdefghjkmnpqrstuvwxyz23456789`, never changes). GitHub Pages serves `404.html` for that path, which `location.replace`s to `/#/t/<qr_code>`; the `t/:code` route (`views/qr`) finds the terrarium (`findByQr`, asking Supabase again if the local copy doesn't have it) and opens its ficha as a scan. The in-app scanner reads the same link (`utils/qr.js` → `parseQrLink`); old number formats (`04`, `filotaxia:04`, `#/terrario/04`) no longer connect. Never print a QR with another domain (`*.github.io`, localhost). `imprimir-qr.html` prints them (error correction H).
- **Camera needs HTTPS** (or localhost). Over the LAN (`http://192.168…`) the scanner shows the "insecure" hint; publish over https to test it on a phone.
- **iPhone audio:** `navigator.audioSession.type = "playback"` so Web Audio plays with the silent switch on; the player resumes the AudioContext when the app comes back to the foreground.
- **iOS caveat:** an installed PWA has its own storage, separate from Safari — terrariums scanned in Safari don't show up in the installed app (scanning again adds them).

### Flow

Splash (`#/inicio`, goes to Mi terrario if there is one, else Escanear) → Conectar (`#/escanear`, in-app camera or "Simular conexión", a dev tool that goes through a terrarium's `#/t/` link) or the phone's own camera opening the QR link → `#/t/<qr_code>` → Ficha (`#/terrario/04`): arriving from a scan (`utils/scan-intent.js`) links the terrarium and the first one ever also becomes Mi terrario; a ficha typed by hand for a terrarium this phone hasn't scanned shows "Sin conectar" and links nothing → "Escuchar" (`#/escuchar/04`, the player). Its **Bitácora** is a separate screen (`#/bitacora/04`), reached from Mi terrario's Bitácora block or the ficha's "Ver su bitácora".

**Escuchar** (`#/escuchar/04`) follows Spotify's now-playing screen: the first screen is the terrarium photo full-bleed (fading into the page) with the controls at the bottom; "Cambiar a video" crossfades to `terrario.video` (none yet: falls back to the Plantas layer GIF). The page scrolls to cards in `views/escuchar/escuchar-bloques.js` (Partitura — two lanes, one per Biodata: Plantas (Biodata 02, succulents) and Sustrato (Biodata 01: substrate, gravel, pumice and ambient), under a playhead synced to the audio; its expand button opens a full-screen `<dialog>` with bigger lanes and the note sounding in each —, Acerca de esta pieza, Plantas (the same `plants-block` as Mi terrario, with its Ondas toggle), Capas, Créditos, Más terrarios); a mini bar with play/pause pins to the top once the big controls scroll away.

**Manifiesto** (`#/manifiesto/04`): on the very first scan (a new link while `manifiesto_seen` is false) the ficha redirects to a 7-screen intro to biosonification (hook: one of the 6 quotes in `content/citas.js`, a different one each time it opens · "Cada capa. Cada planta.": the TR01 product photo (`tr01.jpg`) with frosted-glass (glassmorphism) dots on it, one per layer and one per plant; tapping one explains it below (image and dot positions in `INSIDE_TERRARIUM`, `content/ayuda.js`) · the 4 layers (four stacked horizontal bands, top layer first, one per layer with its GIF from filotaxia.com — `LAYERS` in `content/ayuda.js` —, the lit one opens (taller, in colour, only its name centred over a soft scrim), "(Un terrario, cuatro capas)" on top, "/Capa02" (same size as its text, in the main text colour) + its text below; they cycle every 3.5 s, tapping a band picks it) · leaf → wave grid (leaves first, they flip to their waves after 3 s; two dots at the top right, sitting on the title's last baseline, switch the view) · "(Biosonificación)" + 01/02/03 mechanism · uniqueness · the player itself: `renderPlayer(root, terrario, { embedded: true })` from `views/escuchar` mounts the same player inside the last slide the first time it shows — only its first view (photo + controls), no blocks below, no mini bar, no scroll, no back link / Ajustes; name is an h2 — and taps/arrow keys there belong to the player). Tap/click (left third = back, rest = forward) or arrow keys only — swiping, wheel or trackpad scroll don't move it (`overflow: hidden`; the JS moves it with `scrollTo`), and the page itself can't be dragged; no visible "Siguiente" (a visually-hidden one stays for screen readers); "Saltar" stores `manifiesto_seen` and `location.replace`s to the player; reaching slide 7 also stores it and turns "Saltar" into "Cerrar" → `#/mi-terrario`. Screens 6–7 use the terrarium from `pickTerrario` (the scanned one, else Mi terrario, else the first linked, else TR01). From the bottom nav it opens without id and keeps the bar (`nav` can be a function of ctx; only the first-scan onboarding hides it): "Cerrar" → `#/mi-terrario`. Small copy on every screen follows one rule: a "/Name" label in the main text colour + grey text, both `--font-base`; screens 3 and 5 open with a "(…)" kicker in the main text colour.

Bottom nav (Pulso structure, 5 items): **Mi terrario · Colección · Conectar · Manifiesto · Guía** (labels changed; routes didn't) — Conectar (the scanner, `#/escanear`; UI copy says "Conectar", never "Escanear": brand voice) is the main action, in the center with a black (inverse) background (Mi terrario = the own terrarium's page, route `#/mi-terrario`) (Colección, route `#/coleccion`, lists the whole catalog (from Supabase; retired ones only if already connected) like filotaxia.com, marking the own one and the scanned ones; only connected (scanned) terrariums are enabled and open their player, the rest are greyed out with "Sin conectar" and can't be opened. Scanning is what links it and sets Mi terrario). The scanner is also the small QR in the top-right corner of the Pieza block (and "Conectar mi terrario" while there's no terrarium); Escuchar is opened from the Pieza block, "Escuchar" or a Colección tile; **Ajustes** is the dot at the top right (`components/settings-link`, the 15px circle from filotaxia.com's nav: in the header and in the screens with their own head), with a back arrow to the previous route. **Guía** (`#/filotaxia`, nav section, formerly "Filotaxia", styled like a daily task list) is the user's step-by-step: a "Tu recorrido" progress card (percent + one dot per step) and one row per step (01/ Ubicá · 02/ Conectá · 03/ Escuchá · 04/ Cuidalo · 05/ Bitácora) with a round "Ver" button that opens a sheet with the step's video tutorial, its full text and the button to do it; done steps come from `store/journey.js` (the player marks "escuchado", Cuidados marks "cuidado", step 01 has "Ya lo ubiqué"). Below, "Para saber más" (process, layers, FAQ, Manifiesto).

**Bitácora**: per terrarium (never shared). Each entry: automatic date, required note, optional photo. Text lives in the store (`bitacora` key); photos are shrunk to 1200px JPEG (`utils/image.js`) and stored in IndexedDB (`store/photos.js`) because localStorage only holds ~5 MB of text. Views show them with object URLs and revoke them on leave.

### Mi terrario (`#/mi-terrario`)

Care page modeled on an energy app's "Status." screen: "Filotaxia." + "Armonía en plantas." in grey (the Ajustes dot at the right), the terrarium's code as the hero big number ("TR01", `codeOf()` in `content/terrarios.js`) with a chip with the last connection ("Última conexión", the last time its QR was scanned: arriving through `#/t/<qr_code>` from the QR link or the in-app scanner — not from other screens) and "Escuchar" → the player, then blocks (`components/block`): the terrarium photo full width → its ficha, Bitácora (note count → `#/bitacora/:id`) | Pieza (the piece's duration; the whole block → the player, the QR in its corner → Conectar), Ventilación with a soft meter, Plantas (`components/plants-block`), and a full-width "Cuidados." card → `#/mi-terrario/cuidados`, a subpage with Riego, the general care guide (riego · luz · sustrato, same for every terrarium) and the care FAQ; its route starts with `mi-terrario` so the nav keeps that section active. Air humidity is no longer shown, and the status sentence (`careStatus` in `utils/care.js`) is not used on screen for now. Ventilación is logged by the person ("Ventilé hoy") in `care_log`; Riego has no button for now (it counts from the last logged watering, or from the scan day); humidity drops with the days since the last watering. **Readings are simulated** (seeded by terrarium + day, `utils/care.js`) until terrariums have sensors. Open ecosystems (`care.ventilacion_days: null`) hide Ventilación; terrariums with `plants` show a Plantas block (leaf shape per plant; its "Ondas" toggle swaps to each plant's wave). "Hecho hoy" only reflects a real log entry (`loggedToday`), never the scan-day fallback.

Photos: `terrario.photo` points to `src/assets/images/terrarios/` (the product shots from filotaxia.com's Terrarios page, TR01–06, cropped square at 800px). Plant photos live in `src/assets/images/plantas/` (360px webp) and show in the Plantas block with the plant's wave. The service worker caches them, so they also show offline. `terrariumArt()` draws the sprout underneath, so a missing photo falls back to the drawing.

### Views

Each view exports `title` (string or `(ctx) => string`), optionally `subtitle` (same), `header` (true → big header: title + subtitle + Ajustes dot), `nav` (false → no bar, the splash; or `(ctx) => boolean`: the Manifiesto hides it only in the first-scan onboarding), `back` (string or `(ctx) => string`), and `render(root, ctx)` with `ctx = { params, from }` (`from` = the previous route, e.g. `"coleccion"`). If `render` returns a function, the router calls it when leaving (stop the camera, destroy the audio player). Full-height screens use `.screen` (+ `.screen__actions` pinned to the bottom).

### Data rule

**No view, component or layout file touches `localStorage`, IndexedDB or Supabase directly.** Everything goes through `src/store/` (`store.js`; Bitácora photos via `bitacora.js` → `photos.js`; the catalog via `catalog.js`). To sync with a backend later, replace `collection.js` / `local.js` / `photos.js`; views don't change.

### Components

Plain functions that return HTML strings. **Every user-provided value goes through `escapeHTML()`** (`src/utils/html.js`). Event listeners are attached by the view after inserting the HTML.

### CSS

`src/styles.css` is the single CSS entry; register every new CSS file there under its group. Views and components use **semantic aliases only** (`--color-text`, `--color-line`…), never raw tokens or hex values — otherwise they ignore the theme.

Theme: every alias in `semantic-colors.css` is `light-dark(light, dark)`. **Light is the default** (`prefs.theme: "light"`; `index.html` starts with `data-theme="light"` so there's no dark flash). No `data-theme` = follow the phone ("Auto"); `data-theme="light|dark"` on `<html>` forces it (`utils/theme.js`, from `prefs.theme`, applied in `main.js` before the first render and on every `prefs` change).

Units: an existing token if one fits; otherwise plain `px`. Never `clamp()`, `vw`, `rem`/`em`. Exceptions: `vh`/`dvh` for heights, `%` for widths, `env(safe-area-inset-*)`.

Mobile first (375px is the source of truth). `min-width` media queries only, ascending, at the end of each CSS file after this banner:

```css
/* ============================================
RESPONSIVE
============================================ */
```

Breakpoints: 480 · 640 · 768 · 1024 (bottom nav becomes side rail) · 1280 · 1400.

### File Headers (CSS & JS)

Every CSS and JS file starts with this exact 3-line banner — group and name, separated by an em dash:

```css
/* ============================================
   Views — Escuchar
   ============================================ */
```

Groups: `Tokens`, `Semantic`, `Base`, `Layout`, `Animation`, `Components`, `Views`, `Store`, `Content`, `Audio`, `Utils`, `App`, `Tests`.

### Accessibility baseline

Tap targets ≥ 44px (`--size-tap`), visible focus (`:focus-visible`), icons next to text get `aria-hidden="true"`, the router moves focus to the screen title on navigation, errors are shown with words (not only a color).
